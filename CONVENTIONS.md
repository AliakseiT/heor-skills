# Repository Conventions

These conventions are binding for all contributions (human or agent).

## 1. Country/region-first taxonomy

Jurisdiction is the primary axis everywhere; language is a variant within a jurisdiction.

- Jurisdiction codes: ISO 3166-1 alpha-2 lowercase (`ch`, `de`, `fr`, `us`) plus region code `eu`.
- Language codes: BCP-47 lowercase (`de`, `fr`, `it`, `en`).
- Data: `data/<jurisdiction>/<list>/<version>/<lang>.json` (e.g., `data/ch/migel/2025-07/fr.json`). Language-independent structure (codes, prices, hierarchy) may live in a shared `index.json` per version with per-language label files.
- Skills: jurisdiction-scoped skills carry the jurisdiction prefix (`ch-migel-application`); global/region skills carry none or the region name (`prisma-review`, `eurhta-report`).
- Templates inside skills: `references/templates/<lang>.md`.
- Never name an artifact after its language ("german-form") — name it after its jurisdiction and list, and let language be a parameter.

## 2. Maintenance-minimal, evergreen

- Only markdown, JSON, and dependency-free TypeScript. No servers, no databases.
- Every data file is regenerated by a script in `tools/data-pipeline/` from an official source URL recorded in `tools/data-pipeline/sources.json`. Manual edits to `data/` are forbidden — fix the pipeline instead.
- CI cron runs the pipeline and opens a PR when official sources change; merging is the only maintenance action. Data updates are released as tags (`data-YYYY-MM-DD`).
- All JSON is validated against a schema in `tools/data-pipeline/schemas/` before commit.
- No embeddings in the repo by default. Search scripts are lexical/structured. If embedding search is ever added, vectors are a build-time artifact, never committed source.

## 3. Skills

- One directory per skill under `plugins/heor/skills/<skill-name>/`, `SKILL.md` frontmatter `name` matches the directory name.
- Skill bodies must be harness-neutral (portable beyond Claude Code): no reliance on Claude-specific tools in the core workflow; Claude Code extras (subagents, slash commands, MCP wiring) live at the plugin level.
- Frontmatter `metadata` includes `jurisdiction`, `languages`, `last-verified` (date the regulatory content was last checked against the official source), and `version` (semver — breaking workflow change = major, new reference = minor, fix = patch).
- Numerical work is always delegated to `packages/heor-engine` scripts (`npx tsx <script>`); skills must instruct the agent never to compute model results itself.
- Every skill that drafts regulatory content ends its workflow with an explicit human-review disclaimer step.

## 4. Engine

- `packages/heor-engine`: zero runtime dependencies, pure functions, characterization tests for every model. Behavior changes require a test change in the same commit.
